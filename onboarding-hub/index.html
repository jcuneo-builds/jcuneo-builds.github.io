The problem

Every onboarding started from scratch

Winning a client kicked off weeks of setup that depended on who happened to run it. Ops rebuilt each teamspace by hand, pitch knowledge was scattered across decks, inboxes and Slack, and every team had its own version of "what good looks like".

Before

Teamspace built by hand Pitch context lost in handover Client asked the same questions twice A different process per team

Hours of manual setup per client, inconsistent quality, and client leads spending their first weeks chasing information instead of building the relationship.

After

Triggered by the win Teamspace ready on day one One context every skill reads Pre-filled docs before the client asks 21 steps, one standard

The win in HubSpot starts the process. Skills draft each deliverable from the client's own teamspace, and the team reviews instead of rebuilding.

The brief: take a new client from signed deal to business as usual the same way every time, with ops setup automated end to end and a Claude skill behind every step, so client leads spend onboarding with the client, not in documents.

The solution

One hub, one trigger, a skill for every step

The Onboarding Hub in Notion defines 21 steps across four phases, each with an owner, a template, a worked example and the Claude skill that fills the template in. When a deal closes in HubSpot, the client lands in the Notion client database, which triggers the chain: the first skill builds the teamspace and each skill after it picks up where the last one left off.

How it works

From closed-won to business as usual

Each skill writes into the client's teamspace, and the next one reads from it. The handoff between steps is the teamspace itself.

Architecture

CRM trigger, skill chain, one shared context

The client's Notion teamspace is the system of record. Skills read from it through MCP connectors and write their output back into it.

How it's built

Claude skills, connected to the systems the work lives in

Skills as the unit of automation

Each step's work is packaged as a Claude skill: a versioned set of instructions with its own inputs, outputs and rules. Five were built specifically for onboarding (handover, onboarding docs, 30/60/90, kick-off and discovery decks, audit report), and every skill goes through governance review before it's linked on the hub.

MCP connectors instead of copy and paste

Skills pull from HubSpot for deal and contact data, Gmail and Slack for pitch threads, Google Drive for the pitch folder, fee sheet and SOW, and Notion for everything they write. No one exports or pastes anything between systems.

A shared context layer

The Client Context is a fixed 17-section schema exposed through its own connector. Because every skill reads the same structure, outputs stay consistent with each other, and a correction made once carries into every later draft.

Skills that write real Notion structures

The output isn't text to paste. The teamspace builder repoints database views and filters to the new client, the 30/60/90 builder creates a project with linked tasks and a Gantt timeline, and meeting notes turn into owned tasks in the client's tracker.

Template, skill, example. Every step on the hub pairs one template with the skill that fills it and a worked example of a finished one, so people can see what good looks like before they run anything.
